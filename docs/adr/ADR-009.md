# ADR-009 - Generator and Build Pipeline Architecture

Status: Accepted
Research classification: Documented
Source: `WasteLandForge/research/WastelandForge Generator and Build Pipeline Architecture-deep-research-report.md`

## Decision

WastelandForge outputs are generated through a deterministic, capability-aware build graph.

Generated artifacts are disposable and rebuildable. Every output must carry provenance, at minimum through a local build manifest once build work exists.

## Consequences

- Build inputs must be declared and traceable.
- Generated outputs belong under `generated/` or `dist/`.
- Clean operations must target generated outputs only unless explicitly authorized.
- Build manifests are mandatory for build/release gates.

## Gate Impact

Gate 1 creates disposable output boundaries. Gate 9 implements the first build
manifest and release dry-run evidence. Gate 61 implements the first
deterministic `forge generate` and `forge build` metadata-report outputs, with
generate outputs under `generated/` and build evidence under `dist/`. Gate 62
adds the first game-facing deterministic text output through the
`mcm-json` target, still carrying local manifest and checksum evidence.
Gate 63 validates that generated MCM output against a local output schema
before files are written.
Gate 64 adds deterministic translation INI outputs and records them in local
manifests/checksums.
Gate 65 adds deterministic checkbox and string-toggle option generation while
keeping the same generated/dist output boundaries and manifest evidence.
Gate 66 adds deterministic keybind option generation while keeping the same
generated/dist output boundaries and manifest evidence.
Gate 67 adds deterministic header option generation while keeping the same
generated/dist output boundaries and manifest evidence.
Gate 68 adds deterministic image option map generation while keeping the same
generated/dist output boundaries and manifest evidence.
Gate 69 validates MCM image asset references before generation/build writes
outputs, while keeping the same generated/dist output boundaries and manifest
evidence.
Gate 70 stages validated referenced MCM texture assets under generated/dist
loose-file trees and records those files in manifests, output digests, and
build checksums.
Gate 71 adds deterministic package-manifest metadata for the `mcm-json`
loose-file output tree and records that metadata in manifests, output digests,
and build checksums.
