# ADR-013 - Approval-Bound External Record Authoring Providers

Status: Accepted for planning and preview; execution remains gated
Research classification: Inferred from ADR-004 plus user-supplied R009 evidence
Source:
`WasteLandForge/research/R009 GECK Authoring Plan and Provider Architecture.md`,
`WasteLandForge/research/Fallout New Vegas Asset Pipeline, Content Production and Authoring Workflow-deep-research-report.md`,
ADR-004, ADR-008, ADR-009, ADR-010, and ADR-011

## Context

ADR-004 keeps GECK record editing, xEdit conflict resolution, and raw plugin
editing outside Forge. That boundary correctly prevents Forge core from becoming
a replacement plugin editor, but it did not decide whether Forge may orchestrate
a separately approved external provider that performs record authoring.

R009 identifies a useful narrow workflow where canonical intent is resolved into
a complete plan, executed by a bounded GECK-side provider, and independently
verified through a record-aware xEdit provider.

## Decision

Forge may orchestrate plugin record authoring through an approved external
provider when all of the following are true:

1. Canonical YAML/JSON intent remains authoritative.
2. Forge emits a deterministic, versioned, digest-bound authoring plan before
   execution.
3. Every executable resolution is backed by local evidence.
4. The operator previews and explicitly approves the exact plan digest.
5. The provider is capability-versioned, locally identified, least-privilege,
   and restricted to the approved operations and output.
6. Forge core does not directly write or patch raw ESP/ESM bytes.
7. Provider journals and UI observations are execution evidence, not canonical
   truth.
8. A separate record-aware verifier checks the saved plugin against the approved
   semantic postconditions.
9. Verification failure blocks promotion, packaging, and release readiness.
10. Recovery and rerun policy refuses ambiguous or stale state.

This is a scoped orchestration exception to ADR-004, not a transfer of raw plugin
editing into Forge core.

## First accepted scope

Planning and preview may target only:

- greenfield vanilla Fallout: New Vegas plugins;
- exactly `FalloutNV.esm` as the ordered master set;
- one `CONT` and one placed `REFR`;
- explicit physical or MO2-mediated environment identity;
- no execution while any resolution or provider identity is unresolved.

Execution is not authorized by this ADR alone. It requires subsequent provider
and verifier gates with local evidence.

## Provider roles

- **Planner:** Forge core; deterministic and offline-first.
- **Authoring provider:** preferred GECK-resident xNVSE/GECK Extender adapter.
- **Observation provider:** optional UIA/Win32 sensor; never sole correctness
  authority.
- **Verification provider:** xEdit read-only semantic report.
- **Human operator:** approves exact plan and accepts environment/write effects.

### Host-probe clarification

The first no-mutation provider-host probe may use pinned xNVSE without GECK
Extender. Its only purpose is to prove editor-mode module loading and identity
observation. This exception does not establish an authoring API, authorize
record mutation, remove GECK Extender from the preferred future authoring
environment, or satisfy the execution conditions above.

The probe must be exposed through an explicitly selected MO2 VFS profile so
Forge does not write a native DLL into physical game `Data`. Profile/mod
creation, enablement, ordering, staging, and live launch remain separately
approved operator actions.

## Consequences

- ADR-004 continues to prohibit unrestricted raw plugin editing in Forge.
- A plan is disposable generated output with ADR-009 provenance.
- Approval tokens are invalid after source, resolution, environment, provider,
  output, or policy drift.
- GECK-side implementation and xEdit verification remain optional capabilities,
  not hard requirements for core validation.
- Public fixtures remain synthetic and redistributable.
- Real game masters, Bethesda assets, and third-party plugin bytes are not added
  to the repository.
- UI Automation may observe readiness/modals but cannot establish semantic
  success.
- No approved verification means no claim that authoring succeeded.

## Open checks

- Exact editor-resident APIs available through a local xNVSE/GECK Extender spike.
- Exact xEdit invocation/report contract for `CONT`, `REFR`, TES4 masters,
  ownership, inventory, and transforms.
- Physical Data versus MO2 output policy for the first executable provider.
- Local resolution evidence for the target exterior cell and transform.
