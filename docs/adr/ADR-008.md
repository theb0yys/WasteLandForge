# ADR-008 - Capability Detection and Provider Model

Status: Accepted
Research classification: Documented
Source: `WasteLandForge/research/R005 WastelandForge Capability Detection and Provider Model-deep-research-report.md`

## Decision

WastelandForge projects depend on capabilities, not provider names. Providers are versioned registry data that satisfy capabilities. Detection is local-first and deterministic; runtime probes enrich results.

## Consequences

- Capability requirements are explicit contract data.
- Providers describe how a capability is detected, versioned, scoped, and explained.
- Missing, incompatible, or wrong-scope providers produce diagnostics instead of hidden assumptions.
- Optional capabilities can enable richer generation paths but must not silently become hard requirements.
