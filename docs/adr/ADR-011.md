# ADR-011 - Validation and Release Governance Model

Status: Accepted
Research classification: Documented
Source: `WasteLandForge/research/WastelandForge Validation Testing CI Release and Governance-deep-research-report.md`

## Decision

WastelandForge uses layered validation, deterministic fixture-backed testing, GitHub Actions CI centered on Windows and .NET, immutable published schemas, SemVer-governed version streams, mandatory local build manifests, optional SLSA-style release provenance, least-privilege repository governance, and contribution rules that do not require AI.

## Consequences

- Validation is staged from load/source checks through release validation.
- Canonical issue data is JSON.
- SARIF is the diagnostics exchange format.
- TRX is the native .NET test output.
- Public fixtures must be synthetic and redistributable.
- GitHub Actions must include a mandatory Windows lane once CI exists.
- Release publish flows require governance checks and explicit approval.

## Gate Impact

Gate 7 creates fixture/test structure. Gate 8 creates CI and governance baseline. Gate 9 creates release dry-run and build manifest evidence.
