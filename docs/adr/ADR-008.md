# ADR-008 - Capability Detection and Provider Model

Status: Accepted
Research classification: Documented
Source: `WasteLandForge/research/R005 WastelandForge Capability Detection and Provider Model-deep-research-report.md`

## Decision

WastelandForge projects depend on capabilities, not provider names. Providers are versioned registry data that satisfy capabilities. Detection is local-first and deterministic; runtime probes enrich results.

## Consequences

- Capability requirements are explicit contract data.
- Providers describe how a capability is detected, versioned, scoped, and explained.
- Missing, incompatible, or wrong-scope providers produce diagnostics instead of hidden assumptions.
- Optional capabilities can enable richer generation paths but must not silently become hard requirements.

## Gate Impact

Gate 5 adds capability placeholder validation. Gate 57 adds the first built-in
FNV capability/provider catalogue and exposes it through
`forge capabilities list`; it does not perform local provider detection.
Gate 58 adds explicit path-based provider scan evidence for root-file,
data-file, and executable-tool detectors. Gate 59 adds capability/provider
explanations over that catalogue and scan evidence. Gate 60 resolves declared
project dependency requirements against the built-in catalogue and scan
evidence through `forge capabilities scan --project`. Later gates can add
runtime probes, MO2 effective visibility, version checks, and `WF-CAP-*`
diagnostic projection without changing the project dependency model. Gate 62
uses a declared non-optional `runtime.ui.mcm_json` generation dependency to
gate the first MCM JSON generator path, without treating MCM Extender as a
Forge core dependency. Gate 63 keeps that provider optional while validating
the generated JSON output shape locally. Gate 64 lets authors pass through
MCM Extender runtime `requirements` explicitly, but does not infer those
runtime checks from Forge capability requirements yet. Gate 65 expands the
capability-gated `mcm-json` output subset with checkbox and string-toggle
options without making MCM Extender a Forge core dependency. Gate 66 adds
keybind output to the same capability-gated target without changing provider
requirements.
Gate 67 adds header output to the same capability-gated target without
changing provider requirements.
Gate 68 adds image option output to the same capability-gated target without
changing provider requirements or bundling image/runtime assets.
Gate 69 validates image asset references through source registries without
changing provider requirements.
